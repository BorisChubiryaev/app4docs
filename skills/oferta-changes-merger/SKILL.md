# Объединение изменений в публичную оферту

## Назначение

Из нескольких утверждённых документов «Изменения» собери два файла:

1. **объединённый файл изменений** — перечень правок в порядке следования
   пунктов Оферты;
2. **текст Оферты с внесёнными изменениями**, выделенными цветом.

Исходную Оферту сохраняй побайтно. Юридический текст берётся ТОЛЬКО из
документов «Изменения» — не переформулируй его и не дополняй.

Используй только стандартную библиотеку Python и поставляемый инструмент
`scripts/ofertamerge.py`. Не пересобирай DOCX через LibreOffice, `python-docx`
или самодельные ZIP-замены: это обходит аудит сохранности документа.

## Разделение ролей

Ты определяешь, **что** и **куда** менять, и записываешь это в план. Документ
меняет только инструмент, строго по плану. Это главный принцип: модель не
переписывает оферту, она указывает координаты правок.

## Перед началом

1. Определи абсолютный путь к каталогу этого навыка (каталог со `SKILL.md`).
   Далее — `$SKILL_ROOT`.
2. Полностью прочитай:
   - `references/operations.md` — каталог операций и как выбрать нужную;
   - `references/plan-schema.md` — схема плана перед его созданием.
3. Нужен Python 3.11+. Сеть не требуется.

## Обязательный процесс

### 1. Защити вход и задай результаты

- Проверь, что Оферта и все документы «Изменения» существуют, имеют
  расширение `.docx` и открываются как ZIP.
- Запомни SHA-256 Оферты до работы.
- Вход, обновлённая Оферта, объединённый файл и отчёт — четыре разных пути.
  Никогда не используй вход как `--out-offer`.
- Для `extract`/`plan.json` заведи отдельный рабочий каталог.

### 2. Изучи Оферту

```bash
python3 "$SKILL_ROOT/scripts/ofertamerge.py" inspect "$OFFER" --appendix 1 --points
```

Команда показывает: число сносок в тексте, восстановленные номера пунктов
(в document.xml их НЕТ — их рисует Word) и состав таблицы приложения.

### 3. Извлеки инструкции из каждого документа «Изменения»

```bash
python3 "$SKILL_ROOT/scripts/ofertamerge.py" extract "$IZM" --out "$WORK/izm.json"
```

Получишь абзацы и таблицы. Абзацы — формулировки правок; таблицы — данные
строк для табличных операций. Используй ТОЛЬКО эти тексты.

### 4. Составь план

Классифицируй каждую инструкцию по `references/operations.md` и запиши
UTF-8 JSON строго по `references/plan-schema.md`.

Обязательно для каждой операции указывай `raw_text` — дословную формулировку
из документа «Изменения». Она попадает в объединённый файл и позволяет
оператору сверить правку с первоисточником.

Если инструкция непонятна или её нельзя однозначно привязать к месту в
Оферте — НЕ придумывай операцию. Вынеси её в список ограничений для отчёта.

### 5. Проверь план

```bash
python3 "$SKILL_ROOT/scripts/ofertamerge.py" validate-plan "$WORK/plan.json"
```

Продолжай только при коде выхода `0` и `"ok": true`.

### 6. Примени план

```bash
python3 "$SKILL_ROOT/scripts/ofertamerge.py" apply "$OFFER" "$WORK/plan.json" \
  --out-offer "$OUT_OFFER" --out-combined "$OUT_COMBINED" --report "$REPORT"
```

Инструмент сам выбирает порядок применения: обычные правки — снизу вверх
(чтобы вставка пункта не сдвинула нумерацию ещё не применённых правок), а
алфавитная сортировка — в самом конце, уже после всех замен строк.

Сохрани JSON из stdout как доказательство. Код выхода `2` означает, что часть
операций не применилась: разбери каждую по сообщению, не выдавай результат за
готовый.

### 7. Проведи независимый аудит

```bash
python3 "$SKILL_ROOT/scripts/ofertamerge.py" audit "$OUT_OFFER" --offer "$OFFER" --appendix 1
```

Готовность подтверждай, только когда одновременно выполнено:

- `apply` и `audit` вернули `0` и `"ok": true`;
- SHA-256 исходной Оферты не изменился;
- XML документа и сносок сбалансирован;
- все части исходного пакета сохранены (`source_parts_preserved`);
- число сносок в тексте не уменьшилось (`footnotes_added` ≥ 0);
- в инвариантах приложений `lost_entries` пуст, нумерация подряд, а
  алфавитный порядок соблюдён там, где сортировка запрашивалась.

### 8. Заверши отчёт и ответ

В финальном ответе укажи пути к обоим файлам и отчёту, число применённых и
неприменённых операций, а также предупреждения аудита. Отдельно перечисли
инструкции, которые требуют ручной обработки.

## Когда остановиться без результата

Остановись и назови конкретную причину, если: файл повреждён или зашифрован;
план не проходит валидацию; `apply`/`audit` вернул ошибку; исходная Оферта
изменилась; аудит показал утрату записей приложения или уменьшение числа
сносок. Не выдавай частично проверенный файл за готовый.

## Типичные ошибки

| Ошибка | Правильное действие |
|---|---|
| Искать пункт по НОВОМУ тексту правки | Искать по номеру пункта или имени термина: новой редакции в действующей Оферте ещё нет |
| Заменять строку таблицы по её номеру | Сопоставлять по НАИМЕНОВАНИЮ: номера в документах «Изменения» относятся к другой редакции и легко расходятся |
| Считать «Сноска № 32» элементом с `w:id="32"` | Это 32-я по счёту ссылка в тексте; инструмент сопоставляет сам |
| Вручную пересчитывать номера при вставке пункта | Word перенумеровывает сам, если новый абзац наследует `numPr` соседнего |
| Отсортировать приложение до замены строк | Сортировка идёт последней, иначе переименованные строки нарушат порядок |
| Проверить только непрерывность нумерации | Проверять три инварианта: порядок, отсутствие утрат, корректность сопоставления |
| Переписать формулировку правки «своими словами» | Копировать текст дословно из документа «Изменения» |

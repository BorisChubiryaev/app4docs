# Каталог операций

Как распознать инструкцию из документа «Изменения» и какую операцию выбрать.

## Ключевые особенности Оферты

Прежде чем выбирать операцию, учти три свойства документа — из-за них
«очевидные» подходы не работают:

1. **Номера пунктов в тексте отсутствуют.** `2.44`, `1.2` рисует Word по
   `numbering.xml`. Искать пункт подстрокой «2.44» бесполезно — инструмент
   восстанавливает нумерацию сам, по шаблону `w:lvlText` соответствующего
   уровня. Шаблон бывает с зашитой цифрой раздела: у списка раздела 7 он
   выглядит как `7.%1`, поэтому шестой пункт отображается как «7.6».
   Проверить наличие конкретного пункта: `inspect --point 7.6`.
2. **Сноски нумеруются по порядку ссылок в тексте.** «Сноска № 32» — это
   32-я по счёту `<w:footnoteReference>`, а не элемент с `w:id="32"`.
3. **Номера строк в приложениях нестабильны между редакциями.** Документ
   «Изменения» готовился к той редакции, что была актуальна тогда. Строку
   опознаём по НАИМЕНОВАНИЮ компании.

## Таблица распознавания

| Формулировка в документе «Изменения» | Операция |
|---|---|
| «Сноску N после слов «ЯКОРЬ» дополнить: «ТЕКСТ»» | `insert_after` + `footnote` |
| «Пункт X после слов «ЯКОРЬ» дополнить словами: «ТЕКСТ»» | `insert_after` |
| «Изложить сноску N в следующей редакции: «ТЕКСТ»» | `replace_footnote` |
| «п. X изложить в следующей редакции: «ТЕКСТ»» | `replace_point` |
| «В разделе N «Термины» п. X изложить…» | `replace_point` + `term` |
| «Дополнить пунктом X с последующей перенумерацией: «ТЕКСТ»» | `insert_point` |
| «Пункт X после слов «ЯКОРЬ» дополнить сноской: «ТЕКСТ»» | `add_footnote` |
| «Приложение N … пункты 3, 4, 9 … изложить в следующей редакции» + таблица | `replace_table_rows` |
| «Дополнить таблицу … строками X–Y» + таблица | `append_table_rows` |
| «Изложить Приложение N … в алфавитном порядке, с изменением нумерации» | `sort_table_alpha` |
| «Дополнить Приложение N пунктом … в алфавитном порядке» + строка | `insert_table_row_alpha` |

## Пояснения по операциям

### insert_after

Вставка текста сразу после якорной фразы. Якорь копируй ДОСЛОВНО из
инструкции (то, что стоит после «после слов»). Сопоставление игнорирует
пробелы и кавычки-«ёлочки», поэтому расхождения в них не мешают.

Начинай `payload` с нужного разделителя, чтобы вставка читалась естественно:
`", ООО «ДубльГИС», ООО «НТС»."` или `" код цвета Транспортного средства;"`.

Для сноски укажи `footnote` — её видимый номер. Если номер разойдётся,
инструмент найдёт сноску по якорю и сообщит об этом.

### replace_point

Замена пункта или термина. Указывай `point` (номер) либо `term` (имя
термина). Для термина имя авторитетнее номера — номера терминов «плавают»
между редакциями.

Для пункта приложения дополнительно укажи `appendix` и, если возможно,
`appendix_heading` — заголовок приложения в кавычках из инструкции. Это
сужает поиск номера до нужного раздела: номер `1.2` встречается во многих
списках документа.

### insert_point

Новый пункт. Абзац наследует `numPr` соседнего пункта, поэтому Word
перенумеровывает последующие сам — вручную ничего пересчитывать не нужно.

### add_footnote

Новая сноска: в текст добавляется ссылка после якоря, в `footnotes.xml` —
элемент сноски. Нумерация последующих сносок сдвигается автоматически.

### replace_table_rows

Каждая строка правки — объект `{"number": N, "cells": [...]}`, где `cells`
берутся из таблицы документа «Изменения» как есть, включая первую ячейку с
номером.

Инструмент сопоставляет в два прохода: сначала по наименованию, затем по
номеру — и только если под этим номером стоит та же компания. Если там другая
компания, строка НЕ изменяется, и это попадает в отчёт: так предотвращается
затирание чужой записи.

Ссылки на сноски внутри заменяемых ячеек сохраняются, но переносятся в конец
ячейки — проверь их место. То же правило действует при замене пункта или
термина: ссылки из старого абзаца переносятся в новый, иначе сноска осталась
бы «сиротой», а нумерация всех последующих сносок сдвинулась.

### append_table_rows

Добавление строк в конец таблицы. Строки, уже присутствующие в Оферте (по
наименованию или номеру), пропускаются: правка могла быть применена ранее, и
повторный прогон не должен множить записи.

### sort_table_alpha

Алфавитная пересортировка с перенумерацией. Ключ: организационная форма
(ООО/АО/АНО) отбрасывается, кавычки убираются, регистр не важен, ё=е,
пунктуация значима. Префиксы НКО/ПКО/СК остаются частью названия.

Операция отказывается работать, если в таблице есть настоящее вертикальное
объединение ячеек.

### insert_table_row_alpha

Вставка строки в алфавитную позицию с перенумерацией. Если компания уже есть
в таблице, строка НЕ добавляется — инструмент сообщает номер существующей
записи, чтобы не создать дубликат.

## Что НЕ автоматизируется

Если инструкция не сводится к операции из каталога — не подгоняй её.
Зафиксируй как ограничение и опиши в отчёте, чтобы оператор выполнил вручную.

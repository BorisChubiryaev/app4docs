# Схема плана изменений

План — UTF-8 JSON. Инструмент применяет ТОЛЬКО то, что в нём записано.

## Верхний уровень

```json
{
  "title": "ИЗМЕНЕНИЯ в Публичную оферту «Удобный доступ»",
  "name_column": 1,
  "operations": [ ... ]
}
```

| Поле | Тип | Обязательно | Значение |
|---|---|---|---|
| `title` | строка | нет | Заголовок объединённого файла изменений |
| `name_column` | число | нет | Индекс колонки с наименованием в таблицах приложений (по умолчанию `1`) |
| `operations` | массив | **да** | Непустой список операций |

## Общие поля операции

| Поле | Тип | Обязательно | Значение |
|---|---|---|---|
| `id` | строка | **да** | Уникальный идентификатор (`op1`, `op2`, …) |
| `type` | строка | **да** | Тип из каталога операций |
| `raw_text` | строка | **да** | Дословная формулировка из документа «Изменения» |
| `source` | строка | нет | Реквизиты документа-источника |

`raw_text` попадает в объединённый файл изменений — он должен позволять
оператору сверить правку с первоисточником.

## Поля по типам

| Тип | Обязательные поля | Дополнительно |
|---|---|---|
| `insert_after` | `anchor`, `payload` | `footnote` — для вставки в сноску |
| `replace_point` | `payload` и (`point` или `term`) | `appendix`, `appendix_heading` |
| `insert_point` | `point`, `payload` | — |
| `replace_footnote` | `footnote`, `payload` | — |
| `add_footnote` | `anchor`, `payload` | `point` |
| `replace_table_rows` | `appendix`, `rows` | `name_column` |
| `append_table_rows` | `appendix`, `rows` | — |
| `sort_table_alpha` | `appendix` | `name_column` |
| `insert_table_row_alpha` | `appendix`, `rows` | `name_column` |

### Строки таблицы

```json
"rows": [
  { "number": 3, "cells": ["3", "АО «Интеркомп»", "115432, г. Москва, ..."] }
]
```

`cells` — значения ячеек как есть из таблицы документа «Изменения», включая
первую ячейку с номером. Первая ячейка при замене сохраняется из Оферты:
номер принадлежит действующей редакции.

## Пример

```json
{
  "title": "ИЗМЕНЕНИЯ в Публичную оферту «Удобный доступ»",
  "operations": [
    {
      "id": "op1",
      "type": "insert_after",
      "footnote": 32,
      "anchor": "«ООО СК «Сбербанк Страхование»",
      "payload": ", ООО «ДубльГИС», ООО «НТС».",
      "raw_text": "Сноску 32 после слов «ООО СК «Сбербанк Страхование» дополнить следующими компаниями: «ООО «ДубльГИС», ООО «НТС».».",
      "source": "Изменения № 1"
    },
    {
      "id": "op2",
      "type": "replace_point",
      "term": "Устройство",
      "point": "2.44",
      "payload": "2.44. Устройство – мобильное техническое устройство, телевизор, имеющие доступ к сети Интернет.",
      "raw_text": "В разделе 2 «Термины» п. 2.44. изложить в следующей редакции: «...»",
      "source": "Изменения № 2"
    },
    {
      "id": "op3",
      "type": "replace_table_rows",
      "appendix": "1",
      "rows": [{ "number": 3, "cells": ["3", "АО «Интеркомп»", "115432, г. Москва, ..."] }],
      "raw_text": "Приложение № 1 ... пункты 3, 4, ... изложить в следующей редакции:",
      "source": "Изменения № 74 от 30.03.2026"
    },
    {
      "id": "op4",
      "type": "sort_table_alpha",
      "appendix": "1",
      "raw_text": "Изложить Приложение 1 ... в алфавитном порядке, с соответствующим изменением нумерации.",
      "source": "Изменения № 74 от 30.03.2026"
    }
  ]
}
```

## Проверка

```bash
python3 scripts/ofertamerge.py validate-plan plan.json
```

Валидатор проверяет: непустой `operations`, уникальность `id`, известный
`type`, наличие `raw_text` и обязательных полей типа, непустые `cells`.
Он НЕ проверяет применимость правки к конкретной Оферте — это делает `apply`.

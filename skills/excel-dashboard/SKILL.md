# Дашборд из Excel/CSV

## Что получается

Один файл `.html`: разметка, стили, скрипт и сами данные внутри. Его открывают
двойным кликом, пересылают почтой, кладут в общую папку — интернет и сервер не
нужны. Внутри: строка KPI, панель фильтров, сетка графиков, кросс-фильтрация
(клик по столбцу/сектору фильтрует весь дашборд), таблица с поиском и сортировкой,
кнопка выгрузки отфильтрованных данных в CSV, светлая и тёмная темы.

Агрегация считается в браузере на «сырых» строках — поэтому фильтры живые, а не
предрассчитанные срезы. Это же значит, что данные целиком лежат в файле: держи
объём в разумных рамках (ориентир — до ~100 тыс. строк, иначе файл станет
тяжёлым и медленным).

## Порядок работы

Не пиши HTML, SVG и JS руками: рантайм в `assets/` уже умеет всё перечисленное,
твоя работа — выбрать, **что** показывать, и описать это конфигом. Ручная вёрстка
съедает время и почти всегда получается хуже: без тултипов, без кросс-фильтрации,
с поехавшей тёмной темой.

### 1. Профилируй файл

```bash
python3 scripts/tabledata.py profile "<файл.xlsx|csv>" --out data.json
```

Читает xlsx (несколько листов, даты, общие строки) и csv (utf-8/cp1251, `;`/`,`,
запятая как разделитель дробной части, даты `дд.мм.гггг`) без сторонних библиотек.
Печатает профиль: тип каждой колонки, доля пустых, число уникальных значений,
min/max/сумма/среднее, частые значения и подсказка `role` — `time`, `dimension`,
`measure`, `id`.

Смотри на профиль внимательно: он избавляет от догадок. `role: id` — сквозной
номер, разрезать по нему бессмысленно. `unique: 3` у числовой колонки — это скорее
признак («Скидка»), чем мера. Больше половины пустых — колонку лучше не выносить
в KPI.

Полезные флаги: `--sheet "Продажи"` (или номер листа; список — `sheets <файл>`),
`--header-row 3` (если сверху шапка отчёта и логотипы), `--max-rows 50000`.

### 2. Пойми, ради чего дашборд

Спроси себя — а если непонятно, спроси пользователя: какое решение он принимает
по этим данным? «Где мы теряем деньги», «какой менеджер проседает», «когда пик
обращений» — от ответа зависит состав дашборда. Если пользователь назвал вопрос
сразу, ничего уточнять не нужно: собирай.

Дашборд «на все случаи» получается бесполезным: восемь графиков, ни одного
ответа. Лучше 4–6 блоков, каждый из которых отвечает на конкретный вопрос.

### 3. Опиши состав конфигом

Создай `config.json`. Полная схема — `references/config-schema.md`, выбор типа
графика под данные — `references/chart-choice.md`. Рабочий каркас:

```json
{
  "title": "Продажи 2025",
  "subtitle": "1 200 сделок · январь–декабрь",
  "filters": [
    {"column": "Дата"},
    {"column": "Регион"},
    {"column": "Категория"}
  ],
  "kpis": [
    {"label": "Выручка", "column": "Выручка", "agg": "sum", "format": "money"},
    {"label": "Сделок", "agg": "count"},
    {"label": "Средний чек", "column": "Выручка", "agg": "avg", "format": "money"}
  ],
  "charts": [
    {"type": "line", "title": "Динамика выручки", "dimension": "Дата",
     "bucket": "month", "measure": "Выручка", "agg": "sum", "span": 8},
    {"type": "donut", "title": "Доли каналов", "dimension": "Канал",
     "measure": "Выручка", "agg": "sum", "span": 4},
    {"type": "hbar", "title": "Топ регионов", "dimension": "Регион",
     "measure": "Выручка", "agg": "sum", "limit": 10, "span": 6},
    {"type": "table", "title": "Сделки", "columns": ["Дата", "Регион", "Выручка"],
     "sortBy": "Выручка", "span": 6}
  ]
}
```

Порядок блоков — это порядок чтения: сверху общая картина (KPI и динамика),
ниже разрезы, в конце таблица с деталями. `span` — ширина в сетке из 12 колонок.

### 4. Проверь конфиг и собери

```bash
python3 scripts/build_dashboard.py check config.json --data data.json
python3 scripts/build_dashboard.py build config.json --data data.json --out "Дашборд.html"
```

`check` ловит опечатки в названиях колонок, несовпадение типов (сумма по
текстовому полю), забытый `limit` у разреза с сотней значений, линию по
категориальной оси. Он выводит **все** проблемы разом — чини списком, а не по
одной.

`build` печатает размер файла и число блоков. Если размер вышел за несколько
мегабайт, сузь выборку (`--max-rows`) или заранее сверни данные.

### 5. Проверь глазами и расскажи

Открой получившийся файл и убедись, что он не пустой. Если в окружении доступен
headless-браузер, прогонять его стоит: он ловит то, чего не видно в JSON, —
подписи, налезающие друг на друга, «Нет данных» вместо графика, ошибки в консоли.

Пользователю сообщи не «дашборд готов», а что в нём видно: три-четыре факта из
самих данных («72 % выручки дают два региона», «пик обращений — вторая неделя
марта»), где лежит файл и как им пользоваться (клик по столбцу = фильтр, «Тема»
переключает светлую/тёмную). Ради этих выводов дашборд и собирали.

## Вычисляемые метрики

Маржи, доли, средние на единицу — самые востребованные величины, и их обычно нет
в исходном файле. Добавь колонку прямо в `data.json`:

```bash
python3 scripts/tabledata.py derive data.json --name "Маржа, %" \
  --expr "Прибыль / Выручка * 100"
```

Разрешены имена колонок (можно с пробелами и знаками), числа, арифметика,
сравнения и `abs/round/min/max/int/float`. Строки, где посчитать не вышло
(деление на ноль, пусто), становятся пустыми — счётчик таких строк печатается,
и если он велик, это повод разобраться, а не игнорировать.

## Правки уже собранного дашборда

Дашборд собирается детерминированно из `data.json` + `config.json`, поэтому
любая правка — это правка конфига и повторный `build`. Не редактируй готовый
HTML: следующая пересборка затрёт изменения. Сохраняй `config.json` рядом с
результатом, чтобы к нему можно было вернуться.

Если нужно поменять оформление (палитра, плотность, шрифты) — это `assets/dashboard.css`,
если поведение (новый тип графика, другая логика фильтра) — `assets/dashboard.js`.
Такие правки достаются всем будущим дашбордам, поэтому вноси их осознанно.

## Что доступно в конфиге

Графики: `bar`, `hbar`, `line`, `area`, `stacked-bar`, `pie`, `donut`, `scatter`,
`histogram`, `heatmap`, `table`.
Агрегаты: `sum`, `avg`, `count`, `count_distinct`, `min`, `max`, `median`.
Фильтры: `multiselect`, `range`, `daterange`, `search` (тип подбирается по типу
колонки автоматически, указывать необязательно).
Форматы значений: `money`, `percent`, `compact`, `int`.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| График-«частокол» из сотни столбиков | разрез с большой кардинальностью | `"limit": 10` — остальное свернётся в «Прочие» |
| Круговая диаграмма из 15 секторов | доли не читаются глазом | `hbar` вместо `pie`, либо `limit: 5` |
| Линия скачет между категориями | `line` по нечисловой оси | `bar`/`hbar`, а линию — только по дате |
| «Нет данных при текущих фильтрах» | фильтры взаимоисключающие или колонка почти пустая | проверь `missing` в профиле |
| Числа-даты вида `45678` | csv, где даты выгрузились серийными числами | попроси xlsx или пересчитай через `derive` |
| KPI «средний» с долей «100,2 %» | доля осмысленна только для сумм и счётчиков | не задавай долю для `avg`/`median` — рантайм скрывает её сам |
| Файл на 40 МБ | в дашборд ушли все строки | `--max-rows`, либо сверни данные заранее |

# Проверка PDF → DOCX

Регрессии без пользовательских файлов:

```sh
node --experimental-strip-types --test scripts/table-continuation.test.ts scripts/xml-text.test.ts
```

Проверка скачанного результата (Python 3, стандартная библиотека):

```sh
python scripts/check-docx-tables.py /path/to/result.docx
```

Проверка XML должна выполняться **до** открытия офисным приложением: LibreOffice может восстановить повреждённый файл или экспортировать только его начало без ненулевого кода завершения. После открытия нужно проверить содержимое конца документа, а не только успешный экспорт. Количество страниц Word может отличаться из-за потоковой раскладки.

## Служебные символы PDF

В PDF на 180 страницах воспроизведена ошибка на `docx@9.6.1`: извлечённый текст содержит U+0005–U+0007 и другие управляющие символы, не разрешённые в XML 1.0. Они записывались в `word/document.xml`, после чего парсер прекращал чтение. На `docx@9.15.4` библиотека уже очищает такие символы, поэтому проверка только с последней версией не воспроизводила дефект.

Очистка выполняется в нашем сериализаторе перед созданием текстовых элементов и метаданных, независимо от версии библиотеки. Табуляции, переносы строк, кириллица и допустимые символы вне BMP сохраняются. Пользовательский PDF и производные документы не включаются в репозиторий.
